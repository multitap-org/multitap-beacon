What the beacon is

At home, piccolo and piccoletto find each other on your own network and never use the beacon. Away from home (on mobile data, or from a browser), two devices that are already paired need someone to tell each one where the other is on the internet. That's all the beacon does: it introduces them, then they talk directly.

What goes through it
A few small packets to meet. Your games, picture, sound and controls never do: they go directly between your devices, encrypted end to end, and the beacon can't read them. If your devices can't reach each other directly, they don't connect; the beacon never relays anything.
What it sees
While a piccolo with INTERNET on is online: its public address and port, which every server you talk to sees, and one anonymous meeting id per paired device, a hash the beacon can't tie to a device, a key or a person. Each is forgotten 60 seconds after the piccolo stops refreshing it.
What it keeps
The beacon itself keeps only the counts on this page: how many piccolos are online and how many introductions it made. No accounts, no names, no addresses, no ids, nothing on disk but those counts.
The web server in front
This page, and the WebSocket connection used to meet over WebRTC (a browser, for example), go through an ordinary web server that keeps the usual access log of any website: the visitor's address, the time and what was asked for. That log belongs to the web server, not to the beacon. Introductions over UDP don't go through it.
Who runs it
The Multitap project runs this one. It's free software (MIT): read the code or run your own on GitHub.
